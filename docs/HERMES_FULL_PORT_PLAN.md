# Staged port plan and gap ledger
1. Stage 1, v0.4: pinned audit, matrix, provider catalog, inert skills, deny-by-default plugin manifests, MCP policy primitives, bounded terminal and interval schedule primitives, CLI inspection and tests.
2. Stage 2A, v0.5: native Anthropic/Gemini adapters, normalized tool calls, bounded provider failover, provider selection, and HTTP MCP JSON-RPC behind pre-network tool allowlists. Stage 2B, v0.6: injected-client Bedrock, normalized usage, strict SSE event parsing, shell-free stdio MCP framing, deterministic context compaction and scoped session search. Remaining here: vault-backed OAuth/device flows, end-to-end streaming, SSE MCP and broader conformance.
3. Stage 3A, v0.7: injected vault interface and device-flow polling, redacted auth status, cross-provider streaming event normalization, MCP SSE decoding and bounded ACP JSON-lines/method policy. Stage 3B, v0.8: vault-reference-only connector records, injected full-duplex stream transport, ACP lifecycle/root policy, immutable digest-bound network-disabled container batches, and validated non-overwriting session import/resume. Remaining: platform vault/browser connector, production container backend/PTY, ACP interoperability suite and branching.
4. Stage 4A, v0.9: publisher/signature/capability/digest-gated plugin lifecycle, safe skill install/enable/disable/remove, serializable cron and subscription state with durable cursors and idempotent cleanup. Stage 4B, v0.10: injected isolated plugin runner, signed/digest-pinned HTTPS catalogs, evidence-backed reviewed skill proposals, bounded five-field cron parser/dispatcher, and idempotent source-adapter lifecycle. Remaining: production isolation backend, real catalog publisher keys, concrete source adapters and distributed scheduling.
5. Stage 5: channels/gateway, media, browser/computer use, TUI/desktop, teams, full observability and compatibility harnesses.

Each stage needs unit, integration, golden, migration, security and compatibility coverage. Live services require separately supplied credentials and cannot be claimed tested until run.
